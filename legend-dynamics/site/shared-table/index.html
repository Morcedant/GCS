The shared table

Every character creator can join a shared table: the GM starts one, the players join with a code, and everyone sees the same dice, the same characters and the same fight, each on their own device.

Open a creator Host your own table server Or play with the Discord bot
Running a game
  1. Start the table. In the creator's GM view, under Shared table, name the game and press Start a table. Send the players the link (Copy link) or the six-character code.
  2. Players join. Each opens their character, goes to the play tab, types the code and their name, and presses Join.
  3. Play. Rolls from every sheet are rolled by the table and shown to all. Each character appears on the GM's cards, and injuries, points and ammunition stay in step both ways.
  4. Fight. The GM's battle map and encounter show on every player's play tab. Players move their own tokens and, on their turn, send the GM what they do; the GM puts it into the Encounter panel and runs it.
  5. Keep it private. Anyone with the code can join. The GM can Remove a player and Change code at any time.

Each creator has a How a shared game works guide beside the table, for the GM and for players. The creators on this site already use a table server: nothing to set up. Read on only to host your own.

Host your own table server on Cloudflare

The table server is a small Cloudflare Worker with one Durable Object (a little database) per table. It runs on Cloudflare's free Workers plan, costs nothing while nobody is rolling, and deletes a table nobody has used for 30 days. Everything below works from a browser, an iPad included.

You need: a free Cloudflare account; a GitHub account; and a copy of the Legend Dynamics repository on your GitHub account, with the server's folder, legend-dynamics/table-server, on the branch Cloudflare will build (usually main).

  1. Create a Worker from your repository. In the Cloudflare dashboard, open Workers & Pages and press Create. On the Workers side (not Pages: Pages only serves files and can't run the server), choose Continue with GitHub or Import a repository. The first time, connect GitHub and let Cloudflare see the repository; then pick it.
  2. Fill in the setup. Project name legend-table (it must match the name in the folder's wrangler.toml). Build command: leave it empty. Deploy command: npx wrangler deploy. Preview command, if shown: npx wrangler versions upload. Root directory, often under Advanced settings: legend-dynamics/table-server. No cd in the commands: the root directory takes care of that. Press Deploy.
  3. Check the branch. Cloudflare builds the repository's production branch. If that branch doesn't have the server folder, the build stops with "root directory not found": open the Worker's Settings → Build and set the production branch (it may be called Branch control) to the branch that has it, then retry the build.
  4. Check it's running. The Worker's page shows its address, like https://legend-table.yourname.workers.dev. Open it: it should say Legend Dynamics table server.
  5. Point the creators at it. In any creator's Shared table box, press Another table server… and paste the address; each browser remembers it, so the GM and every player do this once. If you host your own copy of this site, put the address in legend-dynamics/table-server/server-url.txt and rebuild: the creators then use it without asking.
  6. Tidy up (recommended). In wrangler.toml, set ALLOWED_ORIGINS to your site's address (add null if people open the creators as files) so only your pages can use the server. In Settings → Build, set Build watch paths to legend-dynamics/table-server/* so other changes don't rebuild it. In Security → WAF → Rate limiting rules, add one rule (the free plan allows one): about 20 requests a minute per visitor to paths starting with /api/tables.

From a computer instead: in the legend-dynamics/table-server folder, run npx wrangler login and then npx wrangler deploy. The folder's README has the details.

If something goes wrong
What you seeWhat to do
The address ends in pages.dev, or no deploy command was asked forIt was made as a Pages project, which only serves files. Delete it (its Settings, at the bottom) and create it again from the Workers side, as in step 1.
Build log: root directory not foundCheck the root directory is spelled legend-dynamics/table-server exactly, and that the branch being built has that folder (step 3).
Build log: /bin/sh: legend-dynamics/table-server: not foundA command starts with the folder name. With the root directory set, the commands need no cd: just npx wrangler deploy and npx wrangler versions upload.
Build log: pending Durable Object migrationThe first build must be a full deploy, which creates the table storage. Retry the build from your production branch, or set the preview command to npx wrangler deploy for one build, then set it back.
A failed Workers Builds check on other branchesBranches without the server folder can't build it. Set Build watch paths to legend-dynamics/table-server/* (step 6) and they're skipped.
The creator says Couldn't reach the table serverCheck the address you pasted (it starts with https:// and ends in workers.dev) and that opening it in a browser shows the greeting (step 4).
This site isn't allowed to use the table serverYour site isn't in ALLOWED_ORIGINS (step 6). Add its address, or null for creators opened as files, and redeploy.

Updates to the server reach Cloudflare by themselves: each change to the branch it builds deploys again. The creators keep working with an older server, so the site and the server can be updated in either order.
