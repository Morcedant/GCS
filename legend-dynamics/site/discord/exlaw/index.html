Discord commands

The table's Discord bot rolls the dice and keeps the shared Spark points, clocks and Collateral, Scrutiny and Backlash tracks. The bot doesn't know your sheet, so you give it the target number.

Getting started

  1. Type / in the game channel to see every command.
  2. Pick one; Discord shows each option as you fill it in.
  3. Read your target number off your sheet and add up every modifier yourself.

For players

  • /roll target:13 modifier:-2 label:Powers

    Roll 3d6 under your target. Use the number from your sheet, and add up every modifier yourself: circumstance, injury, assistance. The bot shows the result, the margin and your chance. Spend a Spark point to reroll lets you reroll once, and the second result stands.

  • /contest target:13 opponent:13 opponent_name:"White Hand soldier" label:Grapple

    An opposed roll. The bot rolls both sides and names the winner. Ties and double failures go to the defender, which is the opponent unless you add defender:me.

  • /assist target:12 helper_target:14 helper:@name label:"Hold the door"

    Someone helps you. They roll first (Athletics, say): success gives +1, success by 5 or more +2, and a natural 18 brings a complication. Then you roll with their bonus.

  • /points show

    Your Spark points this session. Add player:@name to see someone else's.

  • /points spend

    Spend a Spark point without rolling, e.g. to reduce an injury by one box or to establish a small preparation.

  • /points gain

    Gain a Spark point, e.g. when you accept a complication the GM offers. With Extra Spark, use it once at the start of a session.

  • /track show

    The shared Collateral, Scrutiny and Backlash tracks (Collateral, Scrutiny, Backlash) and what each one means right now.

Only the player who rolled can press the reroll button. Rolls that miss by 1 or 2 remind the GM that success at a cost is on offer.

Clocks

A clock is a circle cut into 2, 4, 6 or 8 segments: 2 for something quick, 4 for urgent or simple, 6 for substantial, 8 for long or complex. A danger clock fills when things go wrong (a failed roll, a success at a cost, time passing), and when it fills the danger happens. A progress clock fills as the characters succeed: one segment for a success, two for success by 5 or more. A chase is a progress clock for the pursuers racing a danger clock for the quarry's escape.

  • /clock show

    Every clock running on this server, with how full each one is.

  • /clock new name:"The breach widens" segments:8 kind:danger

    Start a clock. Use kind:progress for one that fills on successes.

  • /clock tick name:"The breach widens"

    Fill one segment. Add segments:2 for two (success by 5 on a progress clock), or segments:-1 to undo a tick.

  • /clock remove name:"The breach widens"

    Delete a clock once it has filled or no longer matters.

  • /seed

    The adventure seed's last line is a ticking clock, with the /clock new command to start it.

Anyone can start, tick or remove a clock, so players can tick a progress clock after a success; usually the GM runs them. Ticking or removing a clock needs its full name, though capitals don't matter. A server can run up to 20 clocks at once.

For the GM

GM commands need the Manage Server permission on the Discord server. Everyone can see clocks, tracks and points. No bot yet? See Setting up the bot.

  • /game set game:ExLAW

    Choose this server's game. Do it once; /game show checks it.

  • /points newsession

    Start a session: everyone goes back to two Spark points, and unused points are gone.

  • /points gain player:@name

    Award a Spark point, e.g. for an accepted complication.

  • /points set player:@name points:3

    Correct a player's total.

  • /track mark name:collateral

    Mark a box on a track; a partial name works ("collateral" finds Collateral). /track clear clears one, and /track reset clears them all.

  • /seed

    Roll an adventure seed: one line from each seed table, and the command to start its ticking clock.

  • /contest ... defender:me

    When a player resists you (a grapple, a lie, a chase), they are the defender: ties and double failures go to them.

Each server keeps its own points, clocks and tracks. If a command is missing from Discord's list, open the bot's /register page once, then press Ctrl+R in Discord.

Setting up the bot

For the GM, once per group: about 15 minutes, no installs, free. The bot runs on Cloudflare Workers, so there's no server to keep running. One bot serves every game; each Discord server picks its own with /game set.

  1. Create the Discord application

    1. Go to https://discord.com/developers/applications and choose New Application. Name it, e.g. ExLAW Dice.
    2. On General Information, copy the Application ID and the Public Key.
    3. On Bot, choose Reset Token and copy the token. Keep it private; you only need it once, to register the commands.

  2. Create the Worker

    1. Sign up at https://dash.cloudflare.com. It's free, and Workers need no card.
    2. Open Workers & Pages → Create. Choose Start with Hello World!, name it legend-dice, and Deploy the starter. Skip the GitHub and static-file options.
    3. Choose Edit code (top right). Replace everything in the open file with the bot code below, then Deploy.
    4. In the Worker's Settings → Variables and Secrets, add:
      • DISCORD_PUBLIC_KEY = the Public Key
      • DISCORD_APPLICATION_ID = the Application ID
      • DISCORD_BOT_TOKEN = the bot token (type Secret)
      • DEFAULT_GAME = exlaw, so new servers start on ExLAW
    5. Note the Worker's address, like https://legend-dice.YOUR-NAME.workers.dev.

  3. Connect storage

    1. Points, clocks, tracks and /game set need it. In Cloudflare, open Storage & databases → Workers KV → Create and name it legend-store.
    2. Open the legend-dice Worker, then Settings → Bindings → Add → KV namespace. Set Variable name to STORE, pick legend-store and save.
    3. The free plan allows 1,000 storage changes a day, which is plenty for a table.

  4. Connect Discord

    1. On the Discord app's General Information page, paste the Worker address into Interactions Endpoint URL and save. If it saves, the connection works.
    2. Open https://legend-dice.YOUR-NAME.workers.dev/register in your browser. It should say “Registered /roll, /contest, /assist, /points, /clock, /track, /seed and /game.” Then delete DISCORD_BOT_TOKEN from the Worker settings.
    3. On the app's Installation page, make sure Guild Install includes the applications.commands scope. Open the install link and pick your server. The bot needs no other permissions.
    4. In Discord, run /game set game:ExLAW. New commands can take a minute to appear.

If it isn't working

Open the Worker's address in a browser first; what it shows tells you which side to look at.

Opening the Worker address shows “Hello World!”
The bot code wasn't deployed. Paste it again in Edit code and Deploy.
An error page (e.g. 1101)
Only part of the code was pasted. Copy it again and paste the whole thing.
“Legend Dynamics dice bot is running.” with !! lines
A setting is missing or mistyped; the line says which.
“Interactions endpoint URL could not be verified”
The Public Key in Cloudflare doesn't match the app, or the URL is wrong. Use the exact https://…workers.dev address with nothing after it.
/register says “Discord refused the command (401)”
The bot token is wrong or was reset. Reset it on the Bot page and update DISCORD_BOT_TOKEN.
The commands don't appear in Discord
The app isn't installed on that server, or Discord hasn't refreshed. Press Ctrl+R (Cmd+R on a Mac).
“The application did not respond”
The Interactions Endpoint URL points somewhere else, or the Worker code is out of date.
“…need the bot's storage”
Bind the KV namespace as STORE (step 3).
“Only the GM can change the game”
/game set needs the Manage Server permission.
